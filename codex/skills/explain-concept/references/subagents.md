# 서브에이전트 배정

Phase 1에서 사용자가 서브에이전트 트랙을 골랐을 때만 읽는다. 트랙을 고르는 규칙은 SKILL.md의 "두 트랙".
이 파일은 **부모가 하는 일**만 담는다. 서브에이전트에게 넘길 프롬프트는 `agents/`에 파일로 있다.

쪼개서 이득인 것은 **조사와 검산**뿐이다. Phase 2 지식 구조화, lede, Phase 4 작성은 한 머리가 한다.
최상위 "왜"는 모든 섹션을 동시에 들고 있어야 판정되고, 나눠서 합치면 이 스킬이 경고하는 실패
(2차 자료 여러 개를 평균 내다가 핵심 문장을 잃는 것)를 구조로 재현한다.

| 역할 | 언제 | 개수 | 모델 | 프롬프트 |
|---|---|---|---|---|
| 조사원 | Phase 1, 페치 대상 3개 이상 | 문서당 1 | Sonnet with xHigh | `agents/researcher.md` |
| 검증원 | Phase 5, 대조 항목 10개 초과 | 2~4 | 세션 모델 | `agents/verifier.md` |
| 구조 비평가 | Phase 5 | 1 | 세션 모델 | `agents/critic.md` |

**모델을 항상 명시한다.** 조사원은 Sonnet with xHigh, 검증원과 비평가는 세션 모델이다.

## 1. 정찰

검색으로 후보 문서 목록만 만든다. **전문을 열지 않는다.** 목록이 곧 배정표이고, 여기서 나온 개수가
트랙 질문의 근거가 된다.

## 2. 배정

조사원마다 셋을 준다. 하나라도 빠지면 반환이 규격을 벗어난다.

1. 맡을 문서 하나(또는 한 묶음)
2. 고른 관점 목록 전체. 질문지로 쓴다
3. 전체 배정표. 다른 조사원이 맡은 문서를 다시 추천하는 것을 막는다

## 3. 병합

반환을 모은 뒤 두 가지를 한다. 둘 다 부모만 할 수 있는 일이다.

**커버리지 확인.** 빈 관점과 추천 목록을 대조해, 실제로 빈칸을 메우는 자료만 2차 라운드로 배정한다.
**라운드는 2회까지.** 그래도 안 채워지면 "자료 없음, 제외"로 조사 노트에 기록한다.

2차 라운드 규모는 1차 목록 개수를 넘지 않는다. 추천이 쏟아져도 트랙을 다시 고르지 않고 부모가 자른다.

1. 빈 관점을 실제로 메우는가. 이미 답이 있는 관점을 보강만 하는 자료는 뺀다.
2. 1차 자료인가. 같은 내용이면 2차 자료를 먼저 뺀다.
3. 문서에 실제로 들어갈 수치나 인용문이 나올 것 같은가. 배경 읽기용은 뺀다.

잘라 낸 것은 "선정 제외"와 사유 한 줄로 조사 노트에 남긴다. 나중에 빠진 게 실수인지 판단인지 구분된다.

**모순 대조.** 병렬 조사는 관점 간 모순을 놓친다. 조사원마다 자기 문서만 봤기 때문이다. 같은 주장에
값이 다르면 1차를 따르고, 상충한다는 사실을 문서에 적는다.

## 4. 검산 배정

Phase 5에서 트랙을 다시 묻지 않는다. 문서에 실린 수치와 인용문 목록을 뽑아 검증원들에게 나눠 주고,
구조 비평가에게는 완성된 문서만 준다. DRIFT와 NOT FOUND는 문서에서 고치거나 뺀다. "확인 안 됨"으로
남기는 것도 허용한다.
